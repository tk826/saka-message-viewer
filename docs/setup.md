# セットアップ詳細

## メッセージ保存フォルダの構成

メッセージ保存フォルダ（`root`）配下は次の4パターンに対応している。

| | 構成 |
| --- | --- |
| A | `{メンバー}/{YYYY}/{YYYYMM}/{file}` |
| B | `{グループ}/{メンバー}/{YYYY}/{YYYYMM}/{file}` |
| C | `{メンバー}/{file}` |
| D | `{グループ}/{メンバー}/{file}` |

メンバーディレクトリは「`{YYYY}`（数字4桁の名前）のディレクトリを持つ」か「ファイル名規則に合うファイルを直下に持つ」か「取り込み済みのメンバーと同じ名前」かで判定する。どれでもないディレクトリはグループとみなし、その1つ下をメンバーとして探す。

そのため**`{YYYY}/{YYYYMM}` 階層への整形は必須ではない**。ダウンロードしたファイルをメンバーディレクトリ直下に置いたままでも取り込める。

### 直下ファイルと `{YYYY}` ディレクトリが混在する場合

同一メンバー配下に両方があっても、どちらも取り込まれる。たとえば過去分だけ `{YYYY}/{YYYYMM}` に整理済みで、それ以降の新着はメンバー直下に置いている、という状態でよい。

```
日向坂/
  2025/
    202512/
      129000_0_20251201120000.txt   ← 整形済みの過去分
  129074_0_20260723043237.txt       ← 直下に置いた新着分
```

注意点は次の2つ。

- **同じ `msg_id` のファイルを両方に置かない。** `msg_id` が衝突すると1メッセージに統合され、メディアファイルが2つある場合は片方だけが採用される（`[warn] multiple media files` がログに出る）。整理のためにファイルを移動した後に移動元のコピーが残っている、といった状態を作らないこと。上の例のように年・月で置き場所が分かれていれば重複しない。
- **直下ファイルが多いと差分取り込みが遅くなる。** `{YYYY}/{YYYYMM}` 配下はディレクトリ名で対象月だけを開くのに対し、直下ファイルはディレクトリ単位で絞り込めないため、毎回そのメンバーの直下ファイルを全件列挙してファイル名で判定する。直下に数万ファイルが溜まってきたら、ファイル名の日時（UTC）に合わせて `{YYYY}/{YYYYMM}/` へ移しておくとよい。

### 取り込み済みのファイルを移動した場合は全件走査が必要

DBには画像・動画の場所を `root` からの相対パスで持っているため、**取り込み済みのファイルを移動すると、そのパスが古いままになり画像や動画が表示できなくなる**。差分取り込み（既定）は直近2ヶ月分しか見ないので、過去分の移動には追従しない。

移動したら全期間を走査し直す。もっとも簡単なのはWeb UIの設定（&#9881;）→「取り込み」タブで、対象（全メンバー／個別メンバー）を選んで「全期間を取り込む」を実行する方法。CLIなら以下でも同じ。サムネイルとお気に入りはいずれの方法でも保持される。

```powershell
.\message-viewer.exe index --full                          # 全メンバーの全期間
.\message-viewer.exe index --full --only-member "メンバー名"  # 特定メンバーのみ
```

初回取り込みの前に移動しておく場合は、この手順は不要（そのまま取り込めばよい）。

## セットアップ（Windows）

ビルドに次の2つが必要（実行するだけならビルド済みの `message-viewer.exe` があればよく、どちらも不要）。

```powershell
winget install Rustlang.Rustup
winget install Microsoft.VisualStudio.2022.BuildTools --override "--wait --passive --add Microsoft.VisualStudio.Workload.VCTools --includeRecommended"
```

Rust は 1.100 以上が必要（`rust/Cargo.toml` の `rust-version`）。既に入っている場合は `rustup update` で更新する（古いと、ビルドの最初に必要な版を示して止まる）。

Build Tools が既に入っている場合、2つ目は「既存のパッケージ」のアップグレードとして失敗することがあるが、C++ のツールが入っていれば問題ない。インストール後はターミナルを開き直してから、ビルドする。

```powershell
cd \message-viewer
.\build_rust.bat      # rust\ をビルドし、message-viewer.exe をプロジェクト直下にコピー
.\message-viewer.exe  # サーバ起動(エクスプローラからダブルクリックでもよい)
```

ソースを更新したら `build_rust.bat` を再実行する（サーバ起動中は実行ファイルを上書きできないため、止めてから）。

### 別のPCで使う（ビルド環境なし）

`message-viewer.exe` は Visual C++ ランタイムを組み込んでビルドしている（`.cargo/config.toml`）ため、ランタイムの導入は不要。次のものを同じフォルダに置けば動く。

```
message-viewer.exe
config.json        ← 必須（root は空でよい。初回にブラウザの設定画面で指定する）
static\            ← 必須（画面）
ffmpeg.exe         ← 任意（動画サムネイル）
```

起動は `message-viewer.exe` のダブルクリックでよい。

`data\`（`index.db`・`user.db`・`thumbs.db`）は起動時に自動で作られる。
旧版（0.1.x）から更新した場合、旧版のサムネイルフォルダ `data\thumbs\` は起動時に `thumbs.db` へ自動で取り込まれる。
取り込み後は使わないので、旧版に戻さないなら削除してかまわない（ログに「旧サムネフォルダ … は使わなくなりました」と出る）。

設定ファイルと `static\` は、起動したときのカレントディレクトリではなく、`message-viewer.exe` と同じフォルダから探す。

## セットアップ（Linux / WSL）

Rust のツールチェーン（rustup）があればビルドできる。Windows 版と同じく、`static/` と設定ファイルを実行ファイルの隣（または `--config` で指定した設定ファイルの隣）に置く。

```bash
cargo build --release --manifest-path rust/Cargo.toml
./rust/target/release/message-viewer --config ./config.json
```
