# セットアップ詳細

## メッセージ保存フォルダの構成

メッセージ保存フォルダ（`root`）配下は次の4パターンに対応している。

| | 構成 |
| --- | --- |
| A | `{メンバー}/{YYYY}/{YYYYMM}/{file}` |
| B | `{グループ}/{メンバー}/{YYYY}/{YYYYMM}/{file}` |
| C | `{メンバー}/{file}` |
| D | `{グループ}/{メンバー}/{file}` |

メンバーディレクトリは「`{YYYY}` ディレクトリを持つ」か「ファイル名規則に合うファイルを直下に持つ」かで判定する。どちらでもないディレクトリはグループとみなし、その1つ下をメンバーとして探す。

そのため**ファイル整形（`MoveFiles`）は必須ではない**。ダウンロードしたファイルをメンバーディレクトリ直下に置いたままでも取り込める。

### 直下ファイルと `{YYYY}` ディレクトリが混在する場合

同一メンバー配下に両方があっても、どちらも取り込まれる。たとえば過去分だけ `MoveFiles` で整形済みで、それ以降の新着はメンバー直下に置いている、という状態でよい。

```
日向坂/
  2025/
    202512/
      129000_0_20251201120000.txt   ← 整形済みの過去分
  129074_0_20260723043237.txt       ← 直下に置いた新着分
```

注意点は次の2つ。

- **同じ `msg_id` のファイルを両方に置かない。** `msg_id` が衝突すると1メッセージに統合され、メディアファイルが2つある場合は片方だけが採用される（`[warn] multiple media files` がログに出る）。`MoveFiles` で移動した後に移動元のコピーが残っている、といった状態を作らないこと。上の例のように年・月で置き場所が分かれていれば重複しない。
- **直下ファイルが多いと差分取り込みが遅くなる。** `{YYYY}/{YYYYMM}` 配下はディレクトリ名で対象月だけを開くのに対し、直下ファイルはディレクトリ単位で絞り込めないため、毎回そのメンバーの直下ファイルを全件列挙してファイル名で判定する。直下に数万ファイルが溜まってきたら `MoveFiles` で整形するとよい。

### `MoveFiles` によるファイル整形（任意）

`MoveFiles.bat`（実体は `script_ps1\MoveFiles.ps1` と `script_ps1\MergeDatedFolders.ps1`）は、対象ディレクトリに次の2つの前処理を順番に行う。前述のとおり必須ではないが、ファイル数が多い場合は差分取り込みが速くなる。

```powershell
MoveFiles.bat "C:\messages"
```

1. **日付付きフォルダの統合**（`MergeDatedFolders.ps1`）: エクスポートツールによっては、同じメンバーを再ダウンロードした際に `{メンバー}_{YYYYMMDDHHMMSS}` という日付サフィックス付きの別フォルダが作られることがある。これを見つけて統合する。
   - 統合先（サフィックスなしの同名フォルダ）が既にある場合: 日付付きフォルダの中身を統合先へ移動し、空になれば日付付きフォルダを削除する
   - 統合先が無い場合（新規メンバーが日付付きフォルダだけで作られた場合）: フォルダ名から日付を外すリネームのみ行う
   - 同名ファイルが統合先に既にある場合、ファイルサイズが一致すれば同一ファイルの重複とみなし日付付きフォルダ側を削除する。サイズが異なる場合は上書きせずスキップし、日付付きフォルダ側に残す（`msg_id` が衝突していて中身が違うケースなので、内容を見て手動で確認する）
2. **YYYY/YYYYMM階層への整形**（`MoveFiles.ps1`）: ファイル名のタイムスタンプから `{YYYY}/{YYYYMM}/` サブフォルダを作ってファイルを移動する。
   - 対象パターン: `{msg_id(5〜6桁)}_{flag}_{YYYYMMDDHHMMSS}[_{投稿者名}].{jpg|mp4|txt}`（`_{投稿者名}` は colmsg v5 以降が付ける）

いずれの処理も移動済みファイル・同名ファイルが既にある場合はスキップするため、再実行しても安全。日付付きフォルダの統合だけを単独で行いたい場合は `powershell -File script_ps1\MergeDatedFolders.ps1 -TargetDir "C:\messages"` を直接実行する。

#### 取り込み済みのフォルダを整形した場合は全件走査が必要

DBには画像・動画の場所を `root` からの相対パスで持っているため、**整形でファイルを移動すると、そのパスが古いままになり画像や動画が表示できなくなる**。差分取り込み（既定）は直近2ヶ月分しか見ないので、過去分の移動には追従しない。

整形したら全期間を走査し直す。もっとも簡単なのはWeb UIの設定（&#9881;）→「取り込み」タブで、対象（全メンバー／個別メンバー）を選んで「全期間を取り込む」を実行する方法。CLIなら以下でも同じ。サムネイルとお気に入りはいずれの方法でも保持される。

```bash
.\message-viewer.exe index --full                          # 全メンバーの全期間
.\message-viewer.exe index --full --only-member "メンバー名"  # 特定メンバーのみ
```

初回取り込みの前に整形しておく場合は、この手順は不要（そのまま取り込めばよい）。

## セットアップ（Windows）

ビルドに次の2つが必要（実行するだけならビルド済みの `message-viewer.exe` があればよく、どちらも不要）。

```powershell
winget install Rustlang.Rustup
winget install Microsoft.VisualStudio.2022.BuildTools --override "--wait --passive --add Microsoft.VisualStudio.Workload.VCTools --includeRecommended"
```

Build Tools が既に入っている場合、2つ目は「既存のパッケージ」のアップグレードとして失敗することがあるが、C++ のツールが入っていれば問題ない。インストール後はターミナルを開き直してから、ビルドする。

```powershell
cd \message-viewer
.\build_rust.bat      # rust\ をビルドし、message-viewer.exe をプロジェクト直下にコピー
.\message-viewer.exe  # サーバ起動(エクスプローラからダブルクリックでもよい)
```

ソースを更新したら `build_rust.bat` を再実行する（サーバ起動中は実行ファイルを上書きできないため、止めてから）。

### 別のPCで使う（ビルド環境なし）

`message-viewer.exe` は Visual C++ ランタイムを組み込んでビルドしている（`.cargo/config.toml`）ため、ランタイムの導入は不要。次のものを同じフォルダに置けば動く。

```
message-viewer.exe
config.json        ← 必須（root は空でよい。初回にブラウザの設定画面で指定する）
static\            ← 必須（画面）
ffmpeg.exe         ← 任意（動画サムネイル）
```

起動は `message-viewer.exe` のダブルクリックでよい。

`data\`（`index.db`・`user.db`・`thumbs\`）は起動時に自動で作られる。設定ファイルと `static\` は、起動したときのカレントディレクトリではなく、`message-viewer.exe` と同じフォルダから探す。

## セットアップ（Linux / WSL）

Rust のツールチェーン（rustup）があればビルドできる。Windows 版と同じく、`static/` と設定ファイルを実行ファイルの隣（または `--config` で指定した設定ファイルの隣）に置く。

```bash
cargo build --release --manifest-path rust/Cargo.toml
./rust/target/release/message-viewer --config ./config.json
```
